# 画面遷移と取得の改善

- Next.js 16 の Link 自動 prefetch と loading.tsx を組み合わせ、表示中の主要導線のレイアウト・読み込みUIを先読みします。prefetch=trueで投稿や管理一覧全体を長く先読みする設定は使用しません。prefetchはproduction buildで有効です。
- 通常画面と管理画面のloading.tsxはヘッダーを残し、ルートのloading.tsxは認証待ちを含むレイアウト切り替え時に、個人情報のないRelayの外枠を表示します。loadingはNextのSuspense境界です。
- リンクの押下とuseLinkStatusのpendingを表示し、読み込み中も別の導線へ移動できます。スケルトンは小画面対応し、動きを減らすOS設定にも従います。
- React.cacheは同一サーバーレンダーリクエスト内のみ使用します。レイアウトとページのsession()を共有し、以前最大2回ずつだったgetUser・profiles・membershipsを各1回にします。proxyの認証・Cookie更新は維持します。proxyはgetClaimsで署名・期限を検証し、非対称署名なら公開JWKSの再利用でAuthへのgetUser問い合わせを省きます。対称署名ならSDKがAuthへの問い合わせにフォールバックします。ページ側のgetUserは維持します。別リクエスト・別ユーザーへ結果を保存しません。
- profilesとmembershipsは認証確認後に並列取得。マイページはプロフィールを再取得しません。部署名・権限も同じ取得結果を使用します。
- 管理のユーザー、承認詳細、お知らせでは、権限確認後に部署一覧と独立した取得を並列化します。RPC・RLS・各ページと操作の管理権限確認は維持します。
- 既読済み投稿の再訪では既読RPCと、その後のページ全体refreshを省きます。未読の初回訪問では従来どおり既読を保存し、人数表示を更新します。
- 投稿一覧・管理一覧は引き続き動的取得。永続的なユーザー情報キャッシュ、権限のTTL、service workerへの認証済みHTML/RSC保存は追加しません。

## iPhoneでの確認

1. 更新版のVercelビルド完了後、ホーム画面のRelayを一度閉じて開く。
2. 投稿・履歴・マイページ・管理をタップし、押下表示と、必要な場合にスケルトンが出ることを確認。
3. 戻る操作や連続タップ、投稿保存後の一覧更新、初回既読と再訪を確認。
4. 一般ユーザーで管理入口がなく、/admin直接入力でも/appへ戻ることを確認。

自動検証はbuild・型・lint・既存認証/RLSテストと、実際のReact.cacheでのリクエスト単位の再利用・次リクエスト再検証を対象にします。実機の通信速度・表示時間はiPhoneで確認してください。

## 実機確認後の調整

- 全主要リンク（投稿カード・履歴のタブ・承認カード・戻る操作も含む）へ同じ自動prefetchと押下/処理中の背景表示を適用しました。onClickでDB完了を待ってから遷移する処理やrouter.pushの待機はありません。
- 以前のnavigation-progressはロゴにも青い線を表示する原因でした。線を削除し、Safari標準のタップハイライトを抑制。タッチ由来の非focus-visibleのoutlineだけ抑制し、キーボードのfocus-visibleを維持します。
- 通常・管理レイアウトの認証待ちを明示的なSuspenseで囲みました。保護されたメニューやデータを先に表示せず、中立なRelay外枠を表示します。
- 投稿詳細・編集・承認詳細にも個別loadingを追加。投稿詳細の5取得を所属確認後に並列化しました。RLSが各取得の範囲を制限し、投稿が見えなければ詳細を表示しません。編集は投稿者・対応開始の確認を維持します。
- adminDepartmentsもReact.cacheで同じリクエスト内だけ再利用します。最新投稿・所属・権限に長期TTLを導入していません。force-dynamicと認証コールバックのno-storeは非公開データの安全性のため維持します。
- ロゴの装飾点を通常画面・ログイン/登録共通フォームから削除。TEAM WORKSPACE、NEW HANDOVER、ACTIVITY ARCHIVE、MY ACCOUNTを削除しました。日本語見出しは維持します。

実環境のSupabase/Vercel間の距離やコールドスタート、ネットワーク品質は未測定です。今回の修正だけで実機の待ち時間がなくなるとは断定できません。更新版でホームから投稿・履歴・マイページ・管理と各管理機能へ移動し、青線が残らないこと、タップ背景と骨格表示、投稿/権限の更新、縦横スクロールを確認してください。

## タップ表示の継続と文言整理

- 指を離すとCSSのactiveが消え、useLinkStatusのpendingは履歴更新時に終了します。先読み済みの場合もpendingが省略されるため、この2つだけでは反応が途切れることがあります。
- 共通Linkはpointerdownで押下背景を表示し、onNavigateで同期的に遷移中の背景とaria-busyを設定します。通信完了を待つ処理や独自router.pushは追加しません。全主要導線は従来どおり自動prefetchでレイアウト・loadingを先読みします。
- URLのpathnameとqueryの更新で表示を解除します。連続タップでは最新のリンクに切り替え、エラー・ページ離脱時も解除。失敗してURLが変わらない場合の15秒の解除上限は表示だけの制御で、遷移・認証を変更しません。
- pointerの移動・cancel・leaveでは押下表示を解除します。preventDefaultやpointer captureを使わず、縦横スクロールを維持します。新しいアニメーション・青線は追加しません。
- ホーム・投稿・履歴・管理・承認・部署・ユーザーの補助文と、ログインのキャッチコピーを削除。ログイン見出しは「ログイン」。投稿の空状態は「投稿はありません」と「投稿する」のみにします。重要連絡がない範囲の説明カードも表示しません。掲載件数制限・招待・所属承認・編集禁止・部署無効化などの操作上必要な説明は残します。

更新後はiPhoneで短いタップ、長押し後のキャンセル、縦横スクロール、カテゴリの変更、連続タップ、戻る操作を確認してください。押下背景がすぐ表示され、遷移中に反応が途切れず、完了後に残らないことを確認します。実機の速度やVercel/Supabaseの通信時間はこの環境では測定していません。
